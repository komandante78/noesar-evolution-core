PERMISSION NOTE (new finding this phase): the first attempt with
--cap-drop=ALL failed with `error: unexpected argument '--workspace'
found` (cargo metadata has no such flag -- corrected to the valid
invocation, see below) and separately `error: could not find Cargo.toml
in /work or any parent directory`. Root cause of the second error:
--cap-drop=ALL removes CAP_DAC_OVERRIDE, so container-root (uid 0) could
no longer bypass Unix file permissions to read the bind-mounted
staging/rust directory (drwxrwx---, owned by the host claudecode uid,
"other" class = no access). Fixed by adding `--user <host-uid>:<host-gid>`
so the container process's uid matches the mounted files' owner --
avoids needing to loosen any permissions, and is arguably a tighter
posture than relying on CAP_DAC_OVERRIDE anyway. Applied consistently to
every subsequent --cap-drop=ALL container in this phase (metadata, tree,
test, build, both round-trip runs).

COMMAND CORRECTION: the phase spec listed

real cargo has no `--workspace` flag for the `metadata` subcommand (it
already always covers the full workspace by default) -- confirmed via
the literal `error: unexpected argument '--workspace' found` output.
Ran the equivalent valid command instead:
`timeout 300s cargo metadata --locked --offline --format-version 1`

RESULT (after both fixes):
