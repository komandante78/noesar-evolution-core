THE SAME SESSION, FROM A TERMINAL

CodeN Evolution TUI

The terminal shell attached to the same live session as the workbench.

SESSION PROTOCOL BUILT

One program, two shells, joined to the same live session — not a second client with its own state (D-0230). Every command reaches the exact same running workspace-actions/repo-map/event-ledger instances the workbench's own Plan and Terminal panels use.

A browser page cannot spawn a real operating-system shell, so this destination does not simulate one — it names the real program and how to reach it:

node tools/tui-client.mjs [socketPath]

On a container installation, attach to the container the product runs in — there is no SSH daemon inside it, and there should not be. The fast path (D-0348): install the launcher once, then ssh and type one word. On the account you will SSH from, run deployment/container/install-coden-cli.sh — no root, it finds the running installation by its own label and puts coden_evolution on that account's PATH. From then on: ssh you@the-host, then just coden_evolution. The first run asks you to sign in (an attach code minted below, or username/password/second factor); every run after that opens with nothing typed — the client remembers this machine for 90 days, sliding, and coden_evolution --forget revokes it everywhere at once.

Without the launcher installed, the same session is still reachable by hand: ssh you@the-host, then docker exec -it -u 10001 noesar-evolution node /opt/noesar/tools/tui-client.mjs. The socket lives at /run/codev-tui.sock, mode 0600, owned by the product's own uid (it said /run/codev-peer.sock until D-0338 — that is the internal socket, and pointing both at it meant the terminal transport was never served); docs/CODEN_EVOLUTION_TERMINAL_ACCESS.md records the measurements, the CE-021 evidence, the launcher's own security law, and what the two shells deliberately do not share.

From a source installation, run it from a real terminal on this host (or over SSH into it). socketPath defaults to $NOESAR_TUI_SOCKET_PATH, then the product's own tui.sock inside its workspace. The client signs in with the same account as the WebUI — either with an attach code minted below, or with username, password and second factor — then accepts: plan, simulate, approve, reject, restore, get, events, map, search, status, panel <name> (a workbench panel as text, F1…F9 for the first nine bench panels) and the sessions / session-show / session-archive / session-delete / session-restore family.

Navigating it is this page's own mechanism: / lists every address in the product, and /coden/bench/diff — or just /diff — jumps to one. The terminal keeps no list of its own; it asks this server, which reads the addresses off the interface you are looking at, so an address typed in one shell means the same thing in the other. What differs is disclosed rather than smoothed over: the browser hides destinations this account cannot open and the socket cannot, and a panel the terminal has no method for says so instead of printing an empty result.

What this is not: a way to run an arbitrary shell command. Every one of those verbs is one of the product's own already-guarded operations — workspace-actions.mjs refuses EXECUTE and DELETE permanently and on purpose, on both shells alike.

Sign in once

SINGLE SIGN-IN

You are already signed in here. Rather than proving it again to the terminal, mint a short code and type it at the client's first prompt — it opens a session for this same account, with the same permissions.

The code is a claim ticket, not a credential: it carries no permission of its own, it expires in 60 seconds, and spending it destroys it. It can only be redeemed at the terminal socket — no network endpoint accepts it — and minting a second code cancels the first. If it expires while you are typing, mint another; the terminal also still accepts username, password and second factor as before.

ONE LINE · ASK IT THE WAY YOU WOULD SAY IT

Research

A report with compared candidates, the evidence behind each one, and what was not verified.

Takes one line, the way you would say it, and returns a report that is kept until you delete it. Its link needs a session on this installation — it is not public of itself (UI-080…UI-089). Evidence quality is stated per candidate, because reviews can be bought and an average score is not evidence.

Two gates stand in front of it (UI-090…UI-096): on the intent before anything leaves, and on the content that comes back, before it is ever shown — three outcomes, not two (proceed · ask · refuse), each refusal naming its category. It refuses the effect, never the subject: legislation, history, prevention, workplace safety and remediation stay reachable.
